Вариант s=2: k=3, M=4, L=5, d=3, q=5, ε=1/10000.

# Задача 1.1. Моделирование дискретных источников

## Проектные решения

**Формат.** К исходному JSON добавлено необязательное конечное состояние:
начальное распределение, расписания переключателей и переходы после символа.
Оно хранит историю марковского источника либо неизменяемый режим смеси.
Вместо отдельных форматов выбран общий механизм: старые файлы принимаются
без изменений, вероятности считаются переносом массы по состояниям.
Спецификация и примеры — в `docs/SOURCE_FORMAT.md`.

**Арифметика.** Строки вероятностей преобразуются непосредственно в Fraction;
нормировка проверяется точно. Для выборки вероятности приводятся к общему
знаменателю, затем randrange выбирает целочисленный билет. Вариант с float
и допуском отвергнут из-за округления; float используется только при выводе.

## Источники своего варианта

Во всех примерах алфавит {A,B,C}, четыре модели и source длины 5.
Модели A_only, B_only, C_only детерминированные, uniform — равномерная.
Переключатель A выбирает их с весами 1/2,1/4,1/8,1/8, получая распределение
(13/24,7/24,4/24). Переключатели B,C циклически переставляют координаты.

- `iid.json`: одинаковое распределение на каждом такте, независимые символы;
  источник стационарный и эргодический.
- `periodic.json`: расписание A,B,C,A,B; распределение зависит от позиции,
  поэтому источник нестационарный.
- `markov.json`: 27 историй длины 3, initial равномерно. В истории abc
  используется переключатель a, после x история становится bcx.
  Начальное распределение инвариантно, переходы неприводимы и апериодичны:
  источник стационарный, эргодический, с памятью ровно 3.
- `nonergodic.json`: один раз выбирается режим A или B с весами 1/2,1/2.
  Смесь стационарна, но предельные частоты зависят от сохранённого режима:
  источник неэргодический.
- `deterministic.json`: всегда A; проверка вырожденного случая.

# Задача 1.2. Равномерное кодирование источника без памяти

## Метод и арифметика

Источник проверяется точной линейной моделью на парах (состояние, фаза).
Постоянство маргинальных распределений проверяет стационарность на уровне
одного символа; замыкание достижимого линейного базиса доказывает независимость
для всех префиксов. Поэтому недостаточно проверить только блоки длины 2–3.
При нарушении программа указывает нестационарность либо наличие памяти.

Вместо k^n блоков перечисляются типы (n₁,…,nₖ). Их количество
T(n)=C(n+k−1,k−1); блок имеет вероятность ∏pᵢ^nᵢ, мощность типа —
n!/∏nᵢ!. Типы сортируются по вероятности одного блока, выбираются q^ℓ
самых вероятных блоков; последний тип может быть выбран частично.
Полный перебор отвергнут: при k=5, n=50 он требует рассмотреть 5^50 блоков,
тогда как типов 316251. Затраты на одну строку таблицы —
O(k·T(n)+T(n)·log T(n)), память O(k·T(n)).
Это число арифметических операций; их стоимость зависит от разрядности чисел.

Вероятности приведены к общему знаменателю D: числитель блока ∏aᵢ^nᵢ,
знаменатель D^n. Сортировка и сумма покрытой массы используют Python int,
поэтому нет фиксированного переполнения и потери малых вероятностей во float.
Энтропия и округление ℓ вычисляются Decimal с повышением точности у границ;
известные рациональные случаи обрабатываются точно. Неоднозначное округление
даёт диагностику; `--rate H` позволяет задать равенство без округления R вручную.
Порядок типов, блоков и q-ичных кодовых слов определён в `docs/UNIFORM_CODE_FORMAT.md`.

## Результаты

На исходном iid-источнике H≈1.428412468 бит/символ. При R=2 ошибки для
n=1,2,3,4 равны 11/24, 121/576, 11/864, 0: первое подходящее n=4.
При R=1.5 подходящего n≤50 нет, P_e(50)≈0.0669904076, но R>H,
поэтому для всех достаточно больших n условие выполнится.
При R=1 ошибка стремится к 1; при n=50 она ≈0.998204571.

В skewed.json сохранены параметры k=3, M=4, L=5, но P(A)=99999/100000.
При R=0<H подходящими оказываются n=1…10; начиная с n=11 условие
нарушается. Это не противоречит обратной теореме, которая описывает большие n.

Для R=H у неравномерного iid-источника ошибка стремится к 1/2;
для равномерного источника существенны округление ℓ и соотношение q с
мощностью носителя. Эти случаи разобраны отдельно, включая ε=0, 1/2 и 1.
Утверждение о границе ε=1/2 использует поправку −(log₂ n)/2 к минимальному
log₂ M*(n,ε): [Chen, Effros, Kostina, Lossless Source Coding](https://par.nsf.gov/servlets/purl/10232706).

Полные таблицы, описания кодов, диагностики и замер — `RESULTS.md`
и `results/task_1_2/`. Новые тесты сравнивают метод типов с полным перебором,
проверяют частично взятый тип, нулевые вероятности, R=H и границы округления.
Все 52 теста прошли на Python 3.12.13 и 3.13.13. Полный CLI-запуск на
контрольном входе k=5, n_max=50 занял 2.129 с на Python 3.13.13 (лимит 10 с).

При итоговой проверке найдено исключение при выводе точной дроби длиннее
4300 цифр. Вывод переведён на точное преобразование через Decimal(int),
добавлен CLI-тест. Дополнительные рабочие разряды сохраняют точность
энтропии при вероятности, очень близкой к единице. Описание кода проверено
независимым восстановлением небольших кодовых таблиц и обратным декодированием.

# Задача 1.3. Архиватор ZipMeHuffman

## Построение кода

Две очереди весов и массив родителей без кучи и
вложенных узлов. Листья сортируются по (вес, байт), внутренние узлы поступают
во вторую очередь с неубывающими весами. На каждом шаге извлекаются две
наименьшие головы; при равенстве лист предшествует внутреннему узлу.
Длины находятся обратным проходом по массиву родителей. Сортировка стоит
O(m log m), слияния и вычисление глубин — O(m), память — O(m).
Альтернатива — очередь с приоритетом; две очереди выбраны для простого
явного порядка слияний после единственной сортировки.

Канонические слова распределяются по уровням с проверкой свободных мест
по равенству Крафта. Битовый вывод заполняет один байт частями, декодер
распознаёт диапазоны канонических слов каждой длины без обхода дерева.
История прежней реализации и декларация генерации сохранены в SOURCES.md.

## Формат и целостность

Выбран бинарный контейнер ZMH1 с каноническими длинами кодов: модель
занимает 2m байтов, весь заголовок — 30+2m. Альтернативы — частоты
(требуют больше байтов) или явное дерево (компактнее при большом m,
но сложнее сериализовать и проверять). Длины позволяют независимо
восстановить кодовые слова; поля N и B задают размер результата и число
полезных битов. Спецификация — `docs/ZMH_FORMAT.md`.

CRC32 исходных данных проверяет результат распаковки, дополнительная CRC32
фиксированных полей защищает размеры до их использования. Альтернатива —
SHA-256 — требует большего заголовка; для случайных повреждений выбрана CRC32.
Неверная сигнатура, недостающие байты и нарушение структуры/контрольной суммы
имеют разные диагностики. Временный файл становится конечным только после
успешной проверки. При сжатии сверяются частоты и CRC32 обоих проходов.

Пустой файл имеет заголовок 30 байт. Для одного символа сохраняются его
значение и N, кодовое слово пустое: архив занимает 32 байта. В отличие от
варианта с однобитным словом поток повторений не требует битов данных.
