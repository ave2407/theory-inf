# ZMH1 — формат архива задачи 1.3

Все целые поля без знака, порядок байтов big-endian. Архив содержит
служебные поля, компактную модель и битовый поток; имён файлов и дат нет.
Одинаковое содержимое даёт одинаковый архив независимо от пути и времени.

| Смещение | Размер | Поле |
|---:|---:|---|
| 0 | 4 | ASCII-сигнатура и версия `ZMH1` |
| 4 | 8 | N — исходный размер в байтах |
| 12 | 8 | B — количество полезных битов кодового потока |
| 20 | 2 | m — число различных исходных байтов, 0…256 |
| 22 | 4 | CRC32 исходных N байтов |
| 26 | 4 | CRC32 первых 26 байтов архива |
| 30 | 2m | Пары `(байт, длина кода)` в порядке возрастания байта |
| 30+2m | ceil(B/8) | Кодовый поток, MSB-first |

Заголовок занимает **30+2m** байтов, максимум 542. Длина кода занимает один
байт: максимальная глубина полного двоичного дерева с 256 листьями равна 255.
Неполный последний байт дополняется нулями справа. Число B не включает
заполнение, а фактический размер архива должен точно совпадать с таблицей.

## Канонические слова

Пары сортируются по длине, затем по значению байта. Первому слову назначается
0 нужной длины; каждое следующее получается увеличением предыдущего кода
на 1 и сдвигом влево при росте длины. Например, длины A=1, B=2, C=2 дают
A→0, B→10, C→11. При m≥2 длины положительны и должны задавать полное
префиксное дерево: переполнение и неполное дерево — ошибки.

При построении дерева равные веса разрешаются по минимальному байту
поддерева. Кодер сохраняет длины, поэтому декодер не нуждается в частотах
и повторном построении исходного дерева Хаффмана.

## Вырожденные случаи

- Пустой файл: N=B=m=0, CRC32 исходных данных равна 0; размер архива 30.
- Один символ: m=1, длина кода 0, B=0. Декодер повторяет указанный байт N раз
  и проверяет CRC32; размер архива 32 независимо от N.

## Проверки и диагностика

- Чужой формат: сигнатура отличается от ZMH1.
- Обрезанный архив: есть только префикс сигнатуры, не хватает фиксированного
  заголовка, модели или заявленных байтов потока.
- Повреждённый архив: неверна CRC32 служебных полей, некорректна модель,
  есть лишние байты, ненулевое заполнение, незавершённое кодовое слово,
  неверный размер результата либо несовпадение CRC32 восстановленных данных.

Проверка CRC32 служебных полей выполняется до использования N, B и m.
В модели запрещены повторы и неверный порядок байтов; каждый заявленный
символ должен встретиться в результате. Число битов проверяется на
совместимость с N и длинами. Чтение и запись выполняются порциями 64 КиБ;
при декодировании в памяти находятся дерево и один буфер, а не весь файл.

Конечный результат создаётся только после успешного завершения операции.
Сначала используется временный файл в каталоге результата, затем он
публикуется через hard link без перезаписи существующего пути. При ошибке
временный файл удаляется. Сжатие также сравнивает частоты и CRC32 двух
проходов, чтобы заметить изменение исходника во время чтения.

## Статистика

`--stats` показывает эмпирическую H=-Σp log₂p в битах на исходный байт,
среднюю длину B/N в битах, размер заголовка, данных и всего архива.
Коэффициент равен размеру архива / N: меньше 1 — сжатие, больше 1 — рост.
Для N=0 коэффициент null, H и средняя длина определены как 0.
Для двух и более символов Хаффман даёт H≤средняя длина<H+1, но заголовок
и заполнение последнего байта в эту среднюю длину не входят.
